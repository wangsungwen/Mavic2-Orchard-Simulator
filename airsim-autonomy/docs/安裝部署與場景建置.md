# Windows AirSim 安裝部署與實體場景建置

文件查核日期：2026-10-16。此處「實體模擬環境」指在本機執行、含三維場景、碰撞與飛行物理的軟體模擬。若要把真實場地重建成數位場景，見第 4 節；本包沒有包含場地測量資料。

## 1. 套件與版本選擇

| 項目 | 本包採用 | 用途 |
|---|---|---|
| 作業系統 | Windows 10/11 x64 | 本專案部署目標；仍需本機驗收 |
| AirSim 場景 | v1.8.1-windows / Blocks | 官方現成場景，先驗證 RPC 與航點 |
| Python | CPython 3.10 x64 | 與主專案分開的 `.venv` |
| Python 套件 | 見 `requirements.txt` | AirSim 1.8.1、NumPy、舊版 RPC、OpenCV |
| Unreal Engine | 固定 UE 4.27.2 | 僅自建或修改場景需要；不要直接選 UE5 |
| Visual Studio | VS 2022 + C++ 桌面開發 | 僅原始碼編譯需要 |
| 額外 VS 元件 | Windows SDK 10.0.19041、.NET Framework SDK、CMake tools | 按官方建置文件；UE 若要求 v142，再補 VS2019 C++ 工具集 |
| Git | Git for Windows | 取得固定 tag 原始碼 |

原版 AirSim 官網公告不再更新。新版 Project AirSim 是另一個專案，本包使用的是原版 RPC API，不能假定套件與設定通用。[官方公告](https://microsoft.github.io/AirSim/)

實務規劃建議（不是官方最低需求）：先準備 16 GB RAM、獨立顯示卡與 20 GB 空間跑現成小場景；編輯大型場景建議 32 GB RAM、8 GB 以上 VRAM、150 GB 以上可用空間。實際需求隨場景與解析度而變。先執行 `scripts/Doctor.ps1` 查看本機資訊。

## 2. 路徑 A：先跑官方 Blocks，不必安裝 Unreal 編輯器

在 PowerShell 進入專案根目錄，以下命令都從根目錄執行：

```powershell
Set-Location D:\ResearchCodes\Mavic2Autonomy
powershell -NoProfile -ExecutionPolicy Bypass -File .\airsim-autonomy\scripts\Doctor.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\airsim-autonomy\scripts\Setup-Python.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\airsim-autonomy\scripts\Get-Blocks.ps1
Get-ChildItem .\airsim-autonomy\environments\Blocks -Recurse -Filter Blocks.exe
```

`ExecutionPolicy Bypass` 僅作用於這次 PowerShell 程序。腳本不需啟用 venv，不需更動全機執行原則。若沒有 3.10，先從 [Python 3.10.11 官方 Windows 安裝頁](https://www.python.org/downloads/release/python-31011/) 取得 64-bit 安裝器（此為舊版相容用途），安裝 Python launcher，再重跑。不要使用系統預設 3.14 執行這條舊依賴鏈。

下載腳本取得官方 Windows tag 的 Blocks.zip，解壓到本資料夾；網路受限時可從 [Windows release](https://github.com/microsoft/AirSim/releases/tag/v1.8.1-windows) 手動下載。Linux 的 `v1.8.1` release 不是 Windows 場景包。產生的 SHA256 是本機記錄，不代表官方簽章驗證。

啟動腳本會自動尋找 **WindowsNoEditor 下的頂層 Blocks.exe**，不必手動拼接解壓路徑：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\airsim-autonomy\scripts\Start-Simulator.ps1
.\airsim-autonomy\.venv\Scripts\python.exe .\airsim-autonomy\fly.py status
```

2026-10-16 修正：官方 ZIP 實際可能包含 `Blocks/Blocks/WindowsNoEditor`。現在不需傳 `-Exe`；腳本會自動定位，再執行 `Blocks/Binaries/Win64/Blocks.exe`，等待 TCP 41451 就緒。已開啟場景時不重複啟動。`Get-Blocks.ps1` 重跑會沿用已解壓的檔案。

若缺少舊版 DirectX，啟動腳本會呼叫 `Setup-BlocksRuntime.ps1`，從 [Microsoft 官方下載頁](https://www.microsoft.com/en-us/download/details.aspx?id=8109) 所列來源取得約 96 MB 的 June 2010 套件，驗證 Microsoft 簽章後，把 X3DAudio1_7、XAPOFX1_5、D3DCompiler_43、xinput1_3 的 x64 DLL 解壓至模擬器執行檔旁。此流程不執行 DXSETUP、不修改 Windows 系統目錄。安裝包與解壓內容均保留在本包 downloads。若使用自訂環境或缺少其他 runtime，需另依其需求處理。

壓縮檔內層路徑以實際解壓結果為準。腳本以 `-settings` 絕對路徑載入 `config/settings.json`，不用覆寫 Documents 裡的其他 AirSim 設定。[設定檔搜尋規則](https://microsoft.github.io/AirSim/settings/)

場景應出現無人機，`status` 應列出 MavicSim、Home 約 25/121、NED 約 0/0/0。此經緯度只是示範錨點，**不會自動下載該位置的地形**。先用滑鼠觀察示範航線周圍是否有建築物；Blocks 各版本出生點周邊可能有障礙，不保證範例方形路徑暢通。

## 3. 路徑 B：自行編譯 AirSim 與 Unreal 場景

適合需要改建築、道路、地形或碰撞體的工作。先完成 Epic 帳號登入、安裝 UE 4.27.2，再安裝上一節列出的 VS 元件。工具本身可使用既有全機安裝，所有本次專案程式碼放在 `airsim-autonomy`。

開啟 **Developer Command Prompt for VS 2022**（以下是 cmd 指令）：

```bat
cd /d D:\ResearchCodes\Mavic2Autonomy\airsim-autonomy
mkdir vendor
git clone --branch v1.8.1-windows --depth 1 https://github.com/microsoft/AirSim.git vendor\AirSim
cd vendor\AirSim
git rev-parse HEAD
build.cmd
```

固定 tag 避免混用日後變動的主分支。`build.cmd` 會下載第三方依賴並產出 AirLib/Unreal plugin；可能需要較長時間。若已存在 `vendor/AirSim`，檢查版本後直接在該目錄建置，不必再次 clone。

接著在 `vendor/AirSim/Unreal/Environments/Blocks`：

1. 對 `Blocks.uproject` 選擇 UE 4.27，產生 Visual Studio project files；若尚無 plugin，依該目錄的 `update_from_git.bat` 同步已編譯的 plugin。
2. 開啟產生的 solution，以 Blocks 為啟始專案，選 `Development Editor` / `Win64`（介面可能顯示 x64）編譯。
3. 可在 PowerShell 用編輯器明確傳入設定，路徑依安裝位置調整：

```powershell
& 'C:\Program Files\Epic Games\UE_4.27\Engine\Binaries\Win64\UE4Editor.exe' 'D:\ResearchCodes\Mavic2Autonomy\airsim-autonomy\vendor\AirSim\Unreal\Environments\Blocks\Blocks.uproject' '-settings=D:\ResearchCodes\Mavic2Autonomy\airsim-autonomy\config\settings.json'
```

4. 編輯器按 **Play** 後 RPC 才可使用。關閉 Editor Preferences → Use Less CPU when in Background，避免切到 Python 時模擬變慢。

[官方 Windows 建置](https://microsoft.github.io/AirSim/build_windows/)、[固定版本 build.cmd](https://github.com/microsoft/AirSim/blob/v1.8.1-windows/build.cmd)。2026-10-17 已在本機完成 C++／UE 編譯、Editor Play 與 RPC 驗收，詳見 [路徑 B 本機建置紀錄](路徑B本機建置紀錄.md)。

## 4. 建立自己的物理場景／真實場地模型

1. 在 UE 4.27 新建 C++ Blank 專案，例如 `airsim-autonomy/environments/CampusLab`。有自己的測繪模型時，先記錄座標系、尺度、場地原點與高程基準；將 FBX/OBJ 模型匯入 Content。
2. 從已建置的 `vendor/AirSim/Unreal/Plugins` 複製 AirSim plugin 至場景 `Plugins`；啟用 AirSim，重新產生 solution 並編譯。
3. World Settings 的 GameMode Override 設為 **AirSimGameMode**。PlayerStart 放在平坦地面上方適當高度，確認出生時不穿地或從高空墜落。
4. 新手測試場：建立至少 120 × 120 m 平地；UE 單位是 cm，100 m = 10000 cm。示範航線覆蓋北向 0–20 m、東向 0–15 m、高度 10 m；先保留 40 × 40 m 空曠區。
5. 建築、樹與地面要設定可碰撞的 collision。只有可見網格但沒有碰撞體時，飛機可能穿透；以簡單 cube 障礙做碰撞測試。
6. 地圖 X 對北、Y 對東，UE 的 Z 向上；AirSim API 則 Z 向下。世界原點的地理意義由 OriginGeopoint 設定，並非由材質或模型外觀推定。
7. 複製 `config/settings.json` 的 OriginGeopoint 為場地錨點，重啟模擬。重新生成航線或使用同一錨點附近的既有航線，不要只改經緯度而沿用錯誤路線。
8. 逐步加入牆、道路、坡度、風與相機需求；每次先驗證尺度、起點、碰撞與路徑淨空。
9. 打包前設定 Game Default Map，確保 AirSim assets 被 cook；在 `Config/DefaultGame.ini` 的 `[/Script/UnrealEd.ProjectPackagingSettings]` 段加入 `+MapsToCook=(FilePath="/AirSim/AirSimAssets")`，再使用 File → Package Project → Windows 64-bit。輸出仍放在本新增資料夾。

[官方自建環境流程](https://microsoft.github.io/AirSim/unreal_custenv/)；已有 release 場景未必包含可編輯來源，場景素材授權也需依來源處理。

## 5. 排除安裝與連線問題

| 症狀 | 處理 |
|---|---|
| `No module named numpy/msgpackrpc` 出現在安裝中 | 執行 Setup-Python；AirSim 的 setup 會先匯入自身，不能先單獨裝 AirSim |
| NumPy / Tornado / Python 相容錯誤 | 確認命令使用本包 `.venv/Scripts/python.exe` 與 Python 3.10 |
| RPC timeout / connection refused | 場景已啟動且編輯器已按 Play；檢查 TCP 41451、暫停狀態與背景降速 |
| Destination exists | 更新後的下載腳本會沿用完整解壓目錄；若仍拒絕，檢查是否解壓不完整 |
| 找不到 Blocks.exe 路徑 | 不傳 `-Exe`，由啟動腳本自動尋找，不要手動刪除重複的 Blocks 路徑層 |
| 啟動器 9001 / 原生程式 -1073741515 | 本機此次為缺少上述四個 DirectX DLL；更新腳本會部署本地相依檔，再啟動原生程式 |
| MavicSim missing / Home 不符 | 用 Start-Simulator 明確指定設定；關閉多餘場景，重啟後再測 |
| 起飛即碰撞 | 檢查 PlayerStart、地板碰撞體與出生高度 |
| 編譯缺少 v142 / SDK | 在 VS Installer 補相應元件；維持 UE 4.27，避免升級 UE5 |
| 航線越界 | 對齊 CSV 與 OriginGeopoint；不要為了通過檢查任意放寬座標限制 |
| 飛行超時 | 檢查障礙、場景暫停、幀率；檢視 logs 最後狀態，不把超時當成完成 |

本設定的 RPC 僅綁定 localhost。預編譯場景不需要 DJI App Key、ADB 或 Smart Controller。PX4 SITL/HITL 屬後續飛控研究路線，並不會模擬 DJI 的封閉韌體；第一次導入採 SimpleFlight 即可。
