# 室內與戶外導航開發狀態

2026-10-18：使用者確認 Mavic 2 Enterprise Dual、Smart Controller，無額外室內定位設備；先室內、後戶外，分開選擇。

## 本次交付

新增第一版山坡柑橘果園可攜包 `Mavic2Simulator-Orchard-v1-20261018.zip`。包內 Start-Orchard.cmd／Start-Navigation.cmd 啟動果園選點，Start-Blocks.cmd 保留原場景。此為合成場景更新，不代表戶外 GPS 或真機控制已實作。

`navigation_console.py` 提供室內／戶外兩個選項。室內新增「啟動 UE4 選點飛行」，透過 `point_navigation.py` 開啟俯視選點場景，調整高度、確認後控制 AirSim 到點。也可開啟既有一般場景或雙搖桿離線示範；戶外為未實作入口。不會連線真機或切換 APP 飛控模式。操作見 [UE4選點飛行操作](UE4選點飛行操作.md)。

```powershell
Set-Location C:\Users\wangs\Mavic2Autonomy\airsim-autonomy
.\.venv\Scripts\python.exe .\navigation_console.py
```

現有 AirSim、DJI SDK 模擬器與搖桿離線示範是三種不同系統。開啟兩個視窗不表示已完成橋接。

## 室內完成條件

1. UE4 選取地面位置，另設飛行高度；提供目標、航線及座標顯示。
2. 明確定義場地原點、軸向、單位與高度基準。UE4 通常以公分表示世界位置；AirSim NED 以公尺表示，下為正。不可忽略 Pawn 出生位置及地面沉降偏移。
3. 先用 AirSim 的模擬位置完成閉迴路測試；這些位置永遠不能標為真機位置。
4. 接入實際場地定位，提供位置、方向來源、量測時間、品質及座標校準。設備型式尚未決定，因此真機定位適配器尚不能完成。
5. Android 端保留既有前景授權、控制來源互斥及輸入逾時機制；導航需新增到點、超時、定位失效及取消處理，並以實際回授判斷結果。
6. 完成定位與控制驗收後才能提供真機自動到點。失去定位不能宣稱必定懸停；保留現場遙控器接管。

目前 `joystick-dual` 以室內姿態角控制為主，回傳高度／姿態等資訊，沒有已對齊場地的可靠 XY 位置服務。不得以搖桿時間、速度積分或 AirSim 位置替代已驗證的真機定位。機載視覺定位有助飛控穩定，並不自動建立 UE4 場地座標。

## 戶外後續條件

沿用母專案 `app` + `pc-control` 的航點能力；另外校準場地與 WGS84、起飛點及相對高度，實作預覽、上傳、確認執行及真機遙測顯示。不沿用室內的場地座標或自動切換正在飛行的模式。

## 尚未完成

UE4 與 DJI 通訊橋接、室內定位設備整合、真機到點及戶外入口實作尚未完成。本次沒有發出真機控制命令，也沒有實機驗收。既有 AirSim 降落狀態判定問題仍須另行修正；新選點功能採到點懸停，不自動降落。
